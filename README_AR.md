# DBAE Mod Studio — مدير وصانع مودات لعبة Draw Bricks: Advanced Edition

تطبيق أندرويد (Kotlin + Jetpack Compose + Clean Architecture) ينفّذ البنود الأربعة في وثيقتك:
**(1)** هيكل معماري، **(2)** محوّل OBJ → أصول اللعبة مع التجميل، **(3)** حقن الـ APK وإعادة التوقيع، **(4)** واجهة عصرية بمعاينة ثلاثية الأبعاد حيّة.

> **حالة البناء — اقرأها أولاً:** لم أستطع تشغيل Gradle ولا مترجم Kotlin في بيئتي (لا شبكة)، لذلك **الكود لم يُترجَم بعد**.
> تحققتُ من *المنطق* بمحاكاة Python سطراً بسطر على ملفيك الحقيقيين (القسم 6)، وكتبتُ فاحص أقواس/استيرادات، لكن توقّع أخطاء مترجم بسيطة عند أول Sync.

## 1. ما اكتشفته في ملفيك (يصحّح بعض ما في الوثيقة)

فتحتُ `cat.json` و`aerial_vehicle_engine.obj` وبنيتُ المحوّل على **الصيغة الفعلية** لا على الوصف:

| الموضوع | الوثيقة قالت | الواقع في `cat.json` |
|---|---|---|
| الهندسة | Geometry v2 | **حساء مثلثات غير مفهرس**: كل 9 أرقام في `vertices` = مثلث (القطة 1060 مثلثاً)، لا يوجد `faces` |
| `groups` | مجموعات | **رقم لون لكل رأس** (3180 قيمة) يشير إلى عنصر في `userData` |
| `userData` | ألوان | لوحة **ARGB موقّعة** (القطة 7 ألوان، مثلاً `-6842473 = 0xFF979797`) |
| `boneIndices` | — | **عظمة واحدة لكل رأس** (Rigid skinning)، ورؤوس المثلث الواحد تشترك في العظمة |
| `bones` | `pos`,`scl`,`rot` | `pos` **نسبي للأب**، الجذر `Body` أبوه `-1`، والرؤوس بإحداثيات النموذج |
| `metadata` | عدّادات | `vertices`/`normals` = **عدد الأرقام** (9540) لا الرؤوس؛ `animations:0` ولا يوجد مفتاح animations ← **الحركة في كود المحرك حسب أسماء العظام** |
| `normals` | — | مسطّحة تماماً = `normalize(cross(v1-v0, v2-v0))` والالتفاف عكس عقارب الساعة (طابقتُها على كل المثلثات بخطأ ≤ 4e-6) |
| التنسيق | — | JSON مضغوط بلا مسافات، بلا UV، ~141 KB |

**المقاييس:** الخلية الواحدة = **32 وحدة**؛ قطعة المحرك `Model` تملأ `[-16,16]` والقطة ترتفع 96 وحدة (3 خلايا)، وكلاهما متمركز على الأصل.

**الـ OBJ:** تصدير Blender 2.78، مثلثات فقط بصيغة `f v//vn`. فيه `o Model` (الجسم) و`o Blade` (جزء متحرك بمجموعتين `g 0`/`g 1`) و`o Marker-Blade` = **8 رؤوس + 12 سطر `l`** (صندوق أسلاك يحدّد حدود الجزء المتحرك). لذلك المحلّل يتجاهل أسطر `l` ولا يسمح لرؤوس العلامات بالتأثير على الحدود أو التحجيم.

## 2. الهيكل المعماري (اتجاه الاعتماد: presentation → domain ← data)

```
app/src/main/java/com/modstudio/dbae/
├─ ModStudioApp.kt, MainActivity.kt      AppContainer = حقن اعتماديات يدوي
├─ domain/                               كوتلن نقي (لا يعتمد على أندرويد) ← قابل للاختبار على JVM
│  ├─ model/      Models.kt, Rig.kt      الخيارات، الشبكات، النتائج، قوالب الهياكل (مولَّدة آلياً من cat.json)
│  ├─ convert/    ObjParser (+تثليث Ear-clipping، MTL)
│  │              MeshOps (توجيه، مركزة/تحجيم، دمج رؤوس، تبسيط، normals)
│  │              Colorizer (لوحات متناسقة + userData)   Skinner (عظام + ربط الرؤوس)
│  │              Encoders (كاتب JSON/OBJ بصيغة اللعبة)   SoftwareRenderer (معاينة + أيقونات)
│  ├─ usecase/    ConvertModUseCase, PrepareModsUseCase, BuildModdedApkUseCase
│  └─ repository/ Ports.kt               ModRepository, ThumbnailEncoder, ApkToolchain (واجهات)
├─ data/                                 المحوّلات (Adapters)
│  ├─ apk/   ZipRepacker (نسخ خام + محاذاة)  ApkInspector  RegistryTools  ApkSigning (apksig)
│  │         AndroidApkToolchain (+ApkSourceResolver, ApkInstaller)
│  ├─ store/ ModStore (project.json + source.obj)      └─ image/ AndroidThumbnailEncoder
└─ presentation/                         Compose (RTL عربي) + ViewModel واحد
   ├─ StudioViewModel, ModStudioRoot, theme/  ├─ components/ (المعاينة، منتقي اللون…)
   └─ screens/ LibraryScreen · EditorScreen · BuildScreen
tools/mirror_test.py                     محاكاة Python للمنطق + صور تحقق   ·   app/src/test  اختبارات JVM
```

## 3. خط معالجة المجسم (ConvertModUseCase)

1. إبقاء الرؤوس المستخدمة في أوجه فقط (علامات `l` لا تغيّر الحدود) → 2. توجيه (Z-up→Y-up، قلب 180°)
→ 3. مركزة وتحجيم (طول أطول ضلع بالخلايا، أو «إبقاء الأصل» لملفات بوحدات اللعبة)
→ 4. دمج الرؤوس وحذف المثلثات المنحلّة → 5. تبسيط بتجميع الرؤوس عند تجاوز الحد
→ 6. حساب normals (مسطّحة كالقطة، أو ناعمة بزاوية حدّة) → 7. تلوين: لوحة متناسقة + رقم لون لكل مثلث
→ 8. عظام: قالب (ثابت / رباعي كالقطة / **هيكل مأخوذ من شخصيات اللعبة نفسها**) + ربط كل مثلث بأقرب منطقة عظمة.

المخرجات: قطعة → `assets/models/model/<name>.obj` (`o Model`، `v`/`vn`/`f v//vn`)، شخصية → `assets/models/character/<name>.json` بنفس ترتيب مفاتيح اللعبة، وأيقونة PNG شفافة في `assets/piece_image/` بنفس مقاس وامتداد أيقونات اللعبة (يقرؤهما التطبيق من الـ APK).

## 4. خط بناء الـ APK (BuildModdedApkUseCase)

فحص (Central Directory فقط، سريع) → تخطيط العناصر (إضافة/استبدال، منع تصادم الأسماء) → محاولة إضافة الأسماء إلى قوائم اللعبة →
**إعادة كتابة الـ ZIP بنسخ خام** (بلا إعادة ضغط للعناصر القديمة، حذف توقيعات META-INF القديمة وكتلة v2/v3، والإبقاء على محاذاة 4/4096/16384 للعناصر غير المضغوطة مثل `resources.arsc` و`.so`)
→ توقيع **V1+V2+V3** بـ `apksig` بمفتاح RSA-2048 محفوظ في Android Keystore → تحقق `ApkVerifier` → تثبيت عبر `ACTION_VIEW + FileProvider`.

## 5. الاستخدام

المكتبة ← «استيراد OBJ» (يمكنك اختيار `.mtl` معه لأخذ الألوان) ← **المحرر**: النوع (قطعة/شخصية)، الحجم، الاتجاه، normals، الحد الأقصى للمثلثات، الهيكل، الألوان (تعديل اللوحة والأجزاء) مع معاينة حيّة (اسحب للتدوير، اقرص للتكبير) ← احفظ ← حدّد المودات في المكتبة ← **التركيب**: «من المثبّتة» أو اختر APK، اختر *إضافة* أو *استبدال*، ثم «بناء وتوقيع» ← «تثبيت».

## 6. ما تحققتُ منه وما لم أتحقق منه

**تحققتُ (محاكاة Python على ملفيك، شغّلها بنفسك: `python3 tools/mirror_test.py <مجلد الملفين>`):**
- كاتب JSON يعيد إنتاج `cat.json`: نفس ترتيب المفاتيح، `metadata` متطابقة تماماً، كل مصفوفات الأعداد الصحيحة متطابقة، والأعداد العشرية بخطأ ≤ 5e-7.
- حساب المسطّحة يطابق normals اللعبة؛ قالب العظام (المولَّد من cat.json) يعيد مواضع العظام بدقة ويعيد إسناد **98.5%** من مثلثات القطة إلى عظامها الأصلية.
- التثليث (مضلع محدّب/مقعّر/32 ضلعاً)، الـ normals الناعمة (كرة ومكعب)، تجاهل رؤوس العلامات، المركزة والتحجيم. وصورتا `tools/render_*.png` تثبتان أن المصيِّر يرسم القطة الحقيقية بشكل صحيح.

**لم أتحقق منه (بصراحة):**
- ترجمة Kotlin/Gradle، وتشغيل التطبيق على جهاز، وسلوك `apksig` مع مفتاح Keystore على جهازك.
- كل ما يخص **APK اللعبة نفسه** (لم يكن عندي): مكان قوائم أسماء القطع، أسماء/مقاس/امتداد أيقونات `piece_image`، وأسماء عظام الشخصيات غير القطة.

## 7. التشغيل

Android Studio Ladybug (2024.2) أو أحدث ← Open ← Sync (ينزّل Gradle 8.9 وapksig) ← Run على أندرويد 8+ (`minSdk 26`).
أول تثبيت: فعّل «تثبيت التطبيقات غير المعروفة» لهذا التطبيق. الاختبارات: `./gradlew test`.

## 8. محاذير مهمة

1. **التوقيع يختلف عن توقيع مطوّر اللعبة** ← أندرويد يرفض التحديث فوق الأصلية، فيجب **حذف اللعبة الأصلية مرة واحدة** (تُمسح بياناتها المحلية؛ انسخ مبانيك احتياطياً). بعدها تتحدّث نسخك المعدّلة فوق بعضها لأن المفتاح ثابت. المفتاح يضيع إن حذفتَ هذا التطبيق.
2. **قوائم القطع:** إن كانت أسماء القطع مكتوبة داخل `classes.dex` (كما تلمّح الوثيقة) فالقطعة «المضافة» لن تظهر في القوائم؛ لذلك أضفتُ وضع **الاستبدال** (يكتب فوق قطعة موجودة بنفس اسمها وأيقونتها) وهو يعمل دائماً. زر «فحص أماكن القوائم» يخبرك أين تعيش القوائم فعلاً.
3. إن كانت اللعبة مثبّتة كحزم مقسّمة (App Bundle) فاستخدم ملف APK كامل ومفرد، والتطبيق ينبّهك.
4. الأيقونات تُكتب بمحتوى PNG؛ إن كانت أيقونات اللعبة WebP/JPG يُكتب PNG بنفس الامتداد (تقرؤه معظم المحرّكات بالمحتوى لا بالامتداد) مع تحذير.
5. قد يعرض Play Protect تحذيراً لأن التوقيع محلي. للاستخدام الشخصي على نسختك الأصلية؛ لا تعيد توزيع الـ APK المعدّل.

## 9. الخطوات التالية المقترحة

- **حقن القوائم داخل DEX** (`org.smali:dexlib2` — السطر جاهز معلّقاً في `app/build.gradle.kts`) بعد معرفة مكان القوائم من APK حقيقي.
- محرّر عظام يدوي (الاسم/الأب/المحور)، ودعم أنيميشن الأجزاء المتحركة (`Blade` + `Marker-*`).
- استبدال المعاينة بـ SceneView/OpenGL إن احتجتَ مجسمات أثقل (المُصيِّر الحالي CPU ويكفي لآلاف المثلثات).
